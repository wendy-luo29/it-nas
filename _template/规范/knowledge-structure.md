# 知识库目录与分层规范

## 1. 两层分离

| 层 | 位置 | 可变性 | 内容 |
| --- | --- | --- | --- |
| 证据层 | `<Project>/UR-*/`（用户需求、接口文档、数据库文档、研发分析、发布文档） | 不可变快照 | 需求原文、接口契约、评审记录、AC 清单 |
| 结论层 | `<Project>/Common/` + `<Project>/impact-index.yaml` | 可维护 | 业务规则、踩坑、术语、影响索引、变更记录 |

禁止在结论层存放需求原文或接口文档快照；结论层只放经确认的判断与来源引用。

## 2. 目录结构

```text
it-nas/                          # 知识库仓（本库）
├── _template/                    # 模板：规范、规则/踩坑/变更/索引模板、UR 骨架
│   └── 规范/
├── tools/
│   └── knowledge_guard.py        # 一致性校验器
└── <Project>/                    # 知识库根（一个产品线一个目录）
    ├── 项目说明.md
    ├── impact-index.yaml         # 机读影响索引
    ├── Common/                   # 结论层
    │   ├── 知识库索引.md          # 入口索引：按问题导航到规则
    │   ├── 业务规则/
    │   │   └── <module>/<feature>.md      # 业务规则，带 front-matter
    │   ├── 踩坑记录/
    │   │   └── gotcha_NNN_<主题>.md       # 踩坑，编号三位递增
    │   ├── 变更记录/
    │   │   └── yyyy-MM-dd_<主题>.md       # 规则变更记录
    │   └── 参考/
    │       ├── glossary.md                # 术语
    │       ├── db_schema.md               # 关键表结构
    │       └── apifox.md                  # 接口文档入口
    └── UR-xxx-yyyyMMdd/          # 证据层 + 批次产物
```

## 3. 分层规则

| 规则 | 说明 |
| --- | --- |
| 按模块建目录 | `Common/业务规则/<module>/<feature>.md`，禁止按版本建子目录 |
| 版本写在 front-matter | 文件名不带版本号 |
| 编号不复用不跳号 | AC、用例、踩坑编号只增不改 |
| 写入入口唯一 | 只有需求评审通过的环节可写 `Common/业务规则/` |
| 变更同提交 | 规则改动、变更记录与影响索引改动必须在同一提交 |
| 时效复核 | 规则超过 180 天未复核触发告警 |

## 4. 与代码仓的关系

- 知识库只有这一份，代码仓通过 submodule 挂载（`knowledge/<Project>/`），不再另存 `knowledge/` 副本。
- 证据层与结论层都留在本库：需求在 `UR-*/`，确认后的规则升级到 `Common/`。
- 代码仓的 `requirements/` 仅作过渡期存量，新增需求一律落 `UR-*/`。
- 规范（本目录）只放规范与模板，不放任何项目的业务规则。
